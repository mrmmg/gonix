> **اجازه می‌دهید یک هوش مصنوعی مستقیم `/etc/nginx` را ویرایش کند؟**
> احتمالاً نه. برای همین گونیکس راهی در اختیار عامل‌ها می‌گذارد که حتی از دست‌های خودتان هم امن‌تر است.

عاملی که مستقیم فایل‌های Nginx را ویرایش کند، با یک نویسه‌ی اضافه می‌تواند پروداکشن را از کار بیندازد. اما عاملی که از گونیکس
استفاده کند، همان تضمین‌هایی را می‌گیرد که شما می‌گیرید: پشتیبان، `nginx -t`، برگشت خودکار، audit log و تاریخچه‌ی Git.
برای این کار دو ابزار همراه برنامه است.

## Skill

یک skill که به عامل یاد می‌دهد CLI را امن به کار ببرد: اول بررسی کند، پیش از هر تغییر `--dry-run` بزند و هیچ‌وقت دستی به
`/etc/nginx` دست نزند.

```bash
gonix skill install            # برای Claude Code و کاربر شما (~/.claude/skills/gonix)
gonix skill install --project  # فقط برای پروژه‌ی فعلی (./.claude/skills/gonix)
gonix skill print              # چاپ SKILL.md، برای هر عامل دیگر
```

این skill داخل خود برنامه قرار دارد؛ پس همیشه با نسخه‌ای که اجرا می‌کنید هماهنگ است.

## سرور MCP

یک سرور [MCP](https://modelcontextprotocol.io) روی stdio، با ابزارهای تایپ‌دار که هرکدام به یک دستور CLI برمی‌گردند:

```bash
claude mcp add gonix -- sudo -n gonix mcp
```

گزینه‌ی `sudo -n` یعنی *هیچ‌وقت رمز نپرس*. بنابراین یک قاعده‌ی sudoers لازم دارید که به کاربرتان اجازه بدهد `gonix` را بدون رمز
اجرا کند:

```text
# /etc/sudoers.d/gonix  (با visudo ویرایشش کنید)
youruser ALL=(root) NOPASSWD: /usr/local/bin/gonix
```

{{< callout type="warning" >}}
این قاعده به آن کاربر اجازه می‌دهد بدون رمز، Nginx را در سطح root کنترل کند. فقط به حساب‌هایی بدهیدش که به آن‌ها اعتماد دارید، و به
audit log هم تکیه کنید: تغییراتی که عامل‌ها می‌دهند با `actor=mcp` ثبت می‌شود.
{{< /callout >}}

## عامل چطور باید کار کند؟

skill همین چرخه را به عامل یاد می‌دهد، و برای آدم‌ها هم عادت خوبی است:

```bash
sudo gonix host list --json                       # ۱. اول نگاه کن
sudo gonix host add api.example.com \
     --upstream http://127.0.0.1:3000 --dry-run   # ۲. diff را پیش‌نمایش کن
sudo GONIX_ACTOR=claude gonix host add api.example.com \
     --upstream http://127.0.0.1:3000             # ۳. بعد از تأیید، اجرا کن
sudo gonix host show api.example.com --json       # ۴. نتیجه را بررسی کن
sudo gonix check --json                           # ۵. دنبال مشکل بگرد
```

- **دستورهای مخرب `--yes` می‌خواهند.** عامل فقط وقتی آن را می‌گذارد که شما صریحاً همان کار را خواسته باشید.
- **`GONIX_ACTOR=<name>`** تغییرها را در audit log برچسب می‌زند، تا بفهمید چه کسی چه کرده.
- اگر تغییری شکست بخورد، گونیکس **خودش پیکربندی قبلی را برگردانده است**. عامل باید خروجی `nginx -t` را گزارش دهد، نه اینکه دوباره
  با ویرایش دستی امتحان کند.
