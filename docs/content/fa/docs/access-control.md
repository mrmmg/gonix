## رمز عبور با Basic Auth {#basic-auth}

یک «Access List» مجموعه‌ای نام‌دار از کاربران است که می‌شود در چند جا از آن استفاده کرد. گونیکس آن را در یک فایل استاندارد
`htpasswd` نگه می‌دارد، با رمزهای **bcrypt** (رمز اصلی هرگز ذخیره نمی‌شود)، در مسیر `/etc/gonix/accesslists/<name>.htpasswd`.
وقتی آن را به یک هاست یا location وصل کنید، گونیکس این دو خط را اضافه می‌کند:

```nginx
auth_basic "Restricted";
auth_basic_user_file /etc/gonix/accesslists/<name>.htpasswd;
```

در CLI از `host add/set --access-list NAME` استفاده کنید، یا لیست‌ها و کاربران را در TUI مدیریت کنید.

### «گروه worker» یعنی چه؟

این فایل‌ها را در هر درخواست، پردازه‌های **worker** در Nginx می‌خوانند، نه پردازه‌ی master که با root اجرا می‌شود. اگر workerها نتوانند فایل
را بخوانند، Nginx خطای `500` می‌دهد و در لاگ می‌نویسد: `open() ".../<name>.htpasswd" failed (13: Permission denied)`.

برای همین گونیکس هنگام شروع، گروه workerها را پیدا می‌کند (از دستور `user` در `nginx.conf`، وگرنه از `nginx -V`؛ در Debian و Ubuntu
`www-data`، در Arch `http` و در RHEL `nginx`. یا از `access_lists.group` در `gonix.yaml`)، و بعد:

- همان گروه را با دسترسی `2750` به `/etc/gonix/accesslists/` می‌دهد (setgid، تا فایل‌های جدید هم همین گروه را بگیرند)،
- دسترسی هر فایل `*.htpasswd` را روی `0640` با همان گروه می‌گذارد و فایل‌های قبلی را هم درست می‌کند،
- فقط بیت «اجرا برای بقیه» (`o+x`) را به پوشه‌های بالادستی مثل `/etc/gonix` اضافه می‌کند تا workerها بتوانند از آن‌ها رد شوند،
  بی‌آنکه بتوانند محتویات دیگر را ببینند.

{{< callout type="warning" >}}
هش‌های bcrypt به Nginx‌ای نیاز دارند که با libc/crypt‌ای لینک شده باشد که bcrypt را پشتیبانی کند (glibc جدید با libxcrypt و
بیشتر توزیع‌های امروزی همین‌طورند). اگر Nginx شما نمی‌تواند این هش‌ها را تأیید کند، ورودی‌ها را با ابزاری دوباره بسازید که الگوریتمی
تولید کند که `crypt(3)` سیستم شما پشتیبانی می‌کند.
{{< /callout >}}

## لیست IP {#ip-lists}

لیست‌هایی از IP و بازه‌های CIDR برای اجازه دادن یا بلاک کردن، که می‌توانید به یک هاست یا فقط یک location وصلشان کنید.

```bash
sudo gonix iplist create office --mode allow --entries "203.0.113.0/24 198.51.100.7"
sudo gonix host path add example.com /admin/ --upstream http://127.0.0.1:4000 --ip-list office
sudo gonix iplist add office 192.0.2.10        # لیست بزرگ‌تر می‌شود و همه‌ی هاست‌هایی که از آن استفاده می‌کنند به‌روز می‌شوند
```

{{< callout type="info" >}}
**چرا لیست نام‌دار، نه قاعده برای هر هاست؟** وقتی IP دفتر عوض شود، فقط یک جا ویرایشش می‌کنید و همه‌ی هاست‌هایی که به این لیست
اشاره دارند خودکار دنبالش می‌آیند. لیستی که هنوز جایی استفاده می‌شود، حذف نمی‌شود.
{{< /callout >}}

### «یا از دفتر، یا با رمز»

می‌توانید لیست IP را با Basic Auth ترکیب کنید و مشخص کنید چه رابطه‌ای با هم داشته باشند:

```bash
sudo gonix host set app.example.com --ip-list office --access-list team --satisfy any
```

- `--satisfy any`: هرکدام کافی است (کسانی که از دفتر می‌آیند، رمز نمی‌خواهند).
- `--satisfy all`: هر دو شرط باید برقرار باشد.

## بلاک کردن کشورها {#countries}

می‌توانید برای هر هاست کشورها را مجاز یا بلاک کنید. این قابلیت از ماژول `geoip2` در Nginx و یک دیتابیس MaxMind استفاده می‌کند
(مسیر دیتابیس در `geoip.database` تنظیم می‌شود).

```bash
sudo gonix country setup
sudo gonix country create eu-only --mode allow --countries "DE FR NL"
sudo gonix host set shop.example.com --country-list eu-only
```

برای این کار به ماژول شخص ثالث (در Debian و Ubuntu: `libnginx-mod-http-geoip2`) و یک دیتابیس نیاز دارید، مثلاً از `geoipupdate`.

## IP واقعی کاربر {#real-ip}

> **چرا در لاگ‌هایم همه‌ی درخواست‌ها از آدرس کلودفلر می‌آیند؟**
> چون Nginx فقط آدرسی را می‌بیند که به آن وصل شده، و پشت یک پروکسی، آن آدرس مال خود پروکسی است.

این مشکل لیست IP، محدودیت نرخ، لیست کشورها و لاگ‌ها را **همه با هم** خراب می‌کند، چون همه‌شان پروکسی را می‌بینند نه کاربر را.
به گونیکس بگویید به کدام پروکسی‌ها اعتماد کند تا آدرس بازدیدکننده را از هدر forward شده بیرون بکشد:

```bash
sudo gonix realip cloudflare --refresh        # به کلودفلر اعتماد کن، با بازه‌های تازه‌دانلودشده
sudo gonix realip custom --proxies "10.0.0.0/8" --header X-Forwarded-For
sudo gonix realip show
sudo gonix realip disable
```

گزینه‌ی `cloudflare` از بازه‌هایی استفاده می‌کند که همراه برنامه است، و با `--refresh` بازه‌های فعلی را از کلودفلر دانلود می‌کند.

{{< callout type="warning" >}}
اگر سایتتان پشت پروکسی است، این قابلیت را **قبل از** استفاده از لیست IP، محدودیت نرخ یا لیست کشورها روشن کنید. وگرنه همه‌ی آن‌ها
روی آدرس پروکسی کار می‌کنند و با رسیدن یک نفر به سقف محدودیت، همه بلاک می‌شوند.
{{< /callout >}}
